## 什么是互联网？

### 什么是网络？

默认情况下，我们说的网络就是计算机网络的简称，而不是电信网或者有限电视网，**<span style="font-weight:bold;text-decoration:underline">计算机网络 (network) 由若干个结点 (node) 和连接这些结点的链路 (link) 组成</span>**，网络中的结点可以是计算机（也可以称为主机）、集线器、交换机或路由器等，看下图就是一个包含 7 个结点（6 台主机和 1 台交换机）以及 6 条链路的网络

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cHwkjYw1785553361cW.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

为了实现两台计算机的点对点通信，在一个网络中，每台计算机的网卡都会有一个唯一的标识（称为 **<span style="font-weight:bold;text-decoration:underline">MAC 地址</span>**），当一台计算机要给另一台计算机发送数据时，需要在数据包中指明目的主机的 MAC 地址，比如上图 MAC 地址为 A 的主机发送数据给 MAC 地址为 D 的主机，数据包来到交换机后，会根据目的主机的 MAC 地址 D 查询交换表，找到对应转发的接口 4，然后交换机从 4 号接口转发这个数据包给目的主机，这样就**<span style="font-weight:bold;text-decoration:underline">实现了一个网络中的两台主机的通信</span>**

### 什么是互连网？

上面一个网络把许多计算机连接在一起，而**<span style="font-weight:bold;text-decoration:underline">互连网则把许多网络通过一些路由器连接起来（构成了网络的网络）</span>**，看下图的互连网通过 1 个路由器将 3 个网络连在一起，在一个网络中的两台主机通过 MAC 地址通信，而不同网络中的两台主机则通过 IP 地址通信，一个 32 位的 IP 地址包含两部分信息：

- ① 网络号，用于唯一标识一个网络，看下图所有 IP 的前 3 个字节表示 IP 所在的网络的网络号
- ② 主机号，用于唯一标识一个网络中的主机，下图所有 IP 的最后一个字节表示主机号

比如 MAC 地址为 B 的主机的 IP 地址是 10.111.23.<span style="text-decoration:underline">22</span>，它所在的网络的网络号是 10.111.23.0，主机号是 22

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c8tYqMZ1785553361OF.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

现在主机 B 要给主机 C 发送数据，因为这两个主机的网络号相同，处于相同的网络中，那么可以直接通过交换机根据 MAC 地址来转发这个数据包即可；如果主机 A 要给主机 E 发送数据，它俩的网络号不同，即**<span style="font-weight:bold;text-decoration:underline">两台主机位于不同的网络，此时就需要路由器来帮忙转发数据包</span>**。上图路由器有 6 个接口，每个接口都有自己的 IP 地址和 MAC 地址，比如路由器 1 号接口的 IP 地址是 10.111.23.<span style="text-decoration:underline">3</span>、MAC 地址是 J，网络号为 10.111.23.0 的网络通过交换机连接路由器 1 号接口，那么**<span style="font-weight:bold;text-decoration:underline"> 1 号接口称为这个网络的默认网关</span>**，因此 1 号接口的 IP 地址也属于这个网络。同样，5 号和 6 号接口是其他两个网络的默认网关，一台主机要给其他网络的主机发送数据的话，都需要先将数据包发给默认网关，然后由路由器查询路由表来从对应的接口转发数据包

### 什么是互联网？

**<span style="font-weight:bold;text-decoration:underline">互联网（英文是 Internet，也称为因特网）</span>**是一个专用名词，**<span style="font-weight:bold;text-decoration:underline">它指当前全球最大的、开放的、由众多网络相互连接而成的特定互连网，它采用 TCP/IP 协议族作为通信的规则，且它的前身是美国的 ARPANET 网路</span>**，注意互联网和互连网的区别，互连网（英文是 internet）是一个通用名词，它泛指由多个网路通过一些路由器互连而成的网络，在这些网络之间的通信协议可以任意选择，**<span style="font-weight:bold;text-decoration:underline">不一定非要使用 TCP/IP 协议，而互联网则必须采用 TCP/IP 协议作为通信协议</span>**，很明显互联网是一种特殊的互连网，你可以把互联网看成下图这种使用路由器将全球所有的网络连在一起的结构：

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cwzGcaH1785553361WK.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

为了方便讨论问题，很多时候，我们会使用一朵云来表示一个网络，一朵云表示的网络已经包含了网络中的计算机和交换机等网络结点

### ISP

现代的互联网慢慢的变成了**<span style="font-weight:bold;text-decoration:underline">全球范围的多层次 ISP 结构</span>**，看下图，ISP 的全称是 Internet Service Provider，意思是互联网服务提供者，比如中国电信、中国移动和中国联通等公司都是我国最有名的 ISP，**<span style="font-weight:bold;text-decoration:underline">ISP 可以从互联网管理结构申请到很多 IP 地址、同时拥有通信线路以及路由器等连网设备</span>**，ISP 本质上就是负责管理很多的 IP 地址、很多的路由器以及路由器之间的通信线路的。根据提供服务的覆盖面积大小以及所拥有的 IP 地址数目的不同，ISP也分为不同层次的 ISP：主干 ISP、地区 ISP 和本地 ISP，看下图，目前已经覆盖全球的互联网，其主干 ISP 只有十几个，但本地 ISP 有好几十万个

- **<span style="font-weight:bold;text-decoration:underline">主干 ISP </span>**由几个专门的公司创建和维护，服务面积最大 (一般都能够覆盖国家范围)，并且还拥有高速主干网 (例如10 Gbit/s或更高)。不同的网络运营商都有自己的主干 ISP 网络，并且可以彼此互通
- **<span style="font-weight:bold;text-decoration:underline">地区 ISP </span>**是一些较小的 ISP。这些地区 ISP 通过一个或多个主干 ISP 连接起来。它们位于等级中的第二层，数据率也低一些
- **<span style="font-weight:bold;text-decoration:underline">本地 ISP </span>**给用户提供直接的服务，本地 ISP 可以连接到地区 ISP，也可直接连接到主干 ISP。绝大多数的用户都是连接到本地 ISP 的（所以，本地 ISP 也可以称为接入 ISP）。本地 ISP 可以是一个仅仅提供互联网服务的公司，也可以是一个拥有网络并向自己的雇员提供服务的企业，或者是一个运行自己的网络的非营利机构 (如学院或大学)

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/crTxHYk1785553361uH.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

任何机构和个人只要向某个 ISP 交纳规定的费用，就可从该 ISP 获取所需 IP 地址的租用权，并可通过该 ISP 接入互联网。**<span style="font-weight:bold;text-decoration:underline">所谓上网就是指通过某 ISP 获得的 IP 地址接入互联网</span>**。IP 地址的管理机构不会把单个的 IP 地址零星地分配给单个用户，而是把整块的 IP 地址有偿租赁给经审查合格的 ISP，由此可见，现在的互联网已不是某个单个组织所拥有而是全世界无数大大小小的 ISP 所共同拥有的

**<span style="font-weight:bold;text-decoration:underline">互联网交换点 IXP 的主要作用就是允许两个网络直接相连并交换分组，而不需要再通过第三个网络来转发分组</span>**。（这里了解下即可），例如，在上图中的一个 IXP 将一个接入 ISP、大公司 ISP 和一个主干 ISP 连接起来。这样，主机 A 和主机 B 交换分组时，就不必再经过最上层的主干 ISP，而是直接在接入 ISP 和大公司 ISP 之间用高速链路对等地交换分组。这样就使互联网上的数据流量分布更加合理，同时也减少了分组转发的迟延时间，降低了分组转发的费用

## 互联网的组成

互联网的拓扑结构虽然非常复杂，并且在地理上覆盖了全球，但从其工作方式上看，可以划分为网络边缘和核心部分两大块，看下图：

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cY00f751785553457G2.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">①  网络边缘部分：由所有连接在互联网上的主机组成</span>**，这些主机又称为端系统（即位于互联网末端的系统），端系统包括了桌面计算机（比如 PC、Mac 和 Linux 设备）、服务器（比如 Web 和电子邮件服务器等）和移动计算机（比如笔记本电脑、智能手机、平板电脑等）

网络边缘部分的每个端系统中会运行着各种各样的应用程序，比如 Web 浏览器进程、Web 服务器进程等，我们平时说的主机 A 和主机 B 进行通信，实际上是指主机 A 上的某个进程和主机 B 上的另一个进程进行通信

**<span style="font-weight:bold;text-decoration:underline">② 网络核心部分：由大量网络和连接这些网络的路由器组成，</span>**这部分是为边缘部分提供服务的 (提供连通性和交换)，使边缘部分中的任何一台主机都能够与其他主机通信

看下图用加粗线路连接起来的路由器就构成了网络核心部分，端系统经过一个接入 ISP 与互联网（即因特网）相连，接入 ISP 能够提供有线或者无线连接服务

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cbNev781785553456O9.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

在端系统和互联网之间还有一个**<span style="font-weight:bold;text-decoration:underline">接入网，它是指将端系统物理连接到其边缘路由器的网络</span>**，而**<span style="font-weight:bold;text-decoration:underline">边缘路由器是端系统到任何其他远程端系统的路径上的第一台路由器</span>**，在公司和大学校园以及越来越多的家庭环境中，**<span style="font-weight:bold;text-decoration:underline">使用局域网（LAN）将端系统连接到边缘路由器</span>**，尽管有许多不同类型的局域网技术，但是以太网到目前为止是公司、大学和家庭网络中最为流行的接入技术，看下图，以太网用户使用双绞线将端系统（即主机）与一台以太网交换机相连，以太网交换机再和边缘路由器相连，边缘路由器和接入 ISP 中的路由器相连，从而接入到互联网，上图的公司网络中的有线局域网中的端系统就是通过以太网技术接入到互联网

## 分层的体系结构

互联网（因特网）显然是一个极为复杂的系统，在因特网上存在大量的应用程序和协议、各种类型的端系统、分组交换机以及各种类型的链路级传输媒体，对于这种复杂的系统一般会采用分层的体系结构来组织，在学习互联网的分层体系结构之前，我们先来看一个生活中的实际例子（这个例子来源于【计算机网络-自顶向下方法】这本书）

### 如何描述复杂系统？

想象下让你描述飞机航线这个复杂系统，该系统具有票务代理、行李检查、登机口人员、飞行员、飞机、空中航行控制和世界范围的导航系统。描述这种系统的一种方式是，描述当你乘某个航班时，你要采取的一系列动作。你要购买机票，托运行李，去登机口，并最终登上这次航班。该飞机起飞，飞行到目的地。当飞机着陆后，你从登机口离机并认领行李。如果这次行程不理想，你向票务机构投诉这次航班，下图是这一过程：

看上图，我们注意到在每一端都有票务功能；对已经检票的乘客有托运行李功能；对已经检票并已经检查过行李的乘客有登机功能。对于那些已经通过登机口的乘客（即已经经过检票、行李检查和通过登机口的乘客），有起飞和着陆的功能，并且在飞行中，有飞机按预定路线飞行的功能。接下来我们尝试以水平的方式看待这些功能，看下图

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cZ4SO2n1785553523cs.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

可以看到**<span style="font-weight:bold;text-decoration:underline">每个层次与其下面的层次结合在一起，实现了某些功能、服务</span>**：

- 在票务层及以下，完成了一个人从航线柜台到航线柜台的转移
- 在行李层及以下，完成了人和行李从行李托运到行李认领的转移
- 在登机口层，完成了人和行李从离港登机口到到港登机口的转移
- 在起飞/着陆层，完成了一个人和手提行李从跑道到跑道的转移

每个层次通过以下方式提供服务：① 在这层中执行了某些动作 (例如，在登机口层，某飞机的乘客登机和离机)；② 使用直接下层的服务 (例如，在登机口层，使用起飞/着陆层的跑道到跑道的旅客转移服务)

**<span style="font-weight:bold;text-decoration:underline">利用分层的体系结构，这使某层所提供的服务实现易于改变</span>**。只要该层对其上面的层提供相同的服务，并且使用来自下面层次的相同服务，当某层的实现变化时，该系统的其余部分保持不变。例如，如果登机口功能被改变了 (例如让人们按身高登机和离机)，航线系统的其余部分将保持不变，因为登机口仍然提供相同的功能 (人们登机和离机)；改变后，它仅是以不同的方式实现了该功能。对于大而复杂且需要不断更新的系统，改变服务的实现而不影响该系统其他组件是分层的另一个重要优点

### OSI 分层体系结构

航空公司把你从源地址送到目的地，而互联网则是将报文从源主机送到目的主机，我们也可以使用分层体系结构来组织复杂的网络系统，看下图是由国际标准化组织（ISO） 定义的标准 7 层 OSI 网络分层模型，其中物理层、链路层和网络层

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c4wiEqU1785553523cY.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

每一层都通过特定的功能来解决一个问题，层与层之间通过接口协作，共同完成数据的传输。**<span style="font-weight:bold;text-decoration:underline">下 3 层（物理、链路、网络）全网所有网络设备都要处理</span>**（网卡、三层交换机、路由器、防火墙、光猫等） ；**<span style="font-weight:bold;text-decoration:underline">上 4 层（传输、会话、表示、应用）只在端主机（电脑、手机、服务器等）处理</span>**，中间转发设备不解析

#### 1. 物理层（Physical Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：负责在物理介质（如电缆、光纤、无线信道）上传输原始的比特流（0 和 1），定义了机械、电气、功能和规程特性</span>**

具体作用：

- 规定物理设备的接口标准（如网线的 RJ45 接口、光纤的 LC 接口）
- 定义电压信号的表示方式（如高低电平代表 0 和 1）
- 控制数据的传输速率、同步方式（同步 / 异步传输）和传输模式（单工、半双工、全双工）

典型设备：网卡、集线器（Hub）、网线、光纤、中继器

#### 2. 数据链路层（Data Link Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：将物理层的比特流封装成帧（Frame），负责在相邻节点之间的可靠传输（保证发送的帧不会丢失，如果丢失了，那么就重传），解决物理层可能出现的差错（如比特错误）</span>**

具体作用：

- 帧同步：定义帧的开始和结束标识，确保接收方正确识别帧的边界
- 差错控制：通过校验码（如 CRC 循环冗余校验）检测并纠正传输中的错误
- 流量控制：防止发送方发送速度过快导致接收方缓冲区溢出
- 介质访问控制（MAC）：在共享介质（如以太网）中解决多节点竞争信道的问题（如 CSMA/CD 协议）

型设备：交换机（Switch）、网桥（Bridge）

#### 3. 网络层（Network Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：实现不同网络之间的数据传输（即 "主机到主机" 通信中的 "跨网路由"），核心是路由选择和逻辑寻址</span>**

具体作用：

- 逻辑寻址：为网络中的设备分配唯一的逻辑地址（如 IP 地址），区分不同网络中的节点
- 路由选择：通过路由算法（如 OSPF、RIP）选择从源网络到目标网络的最佳路径
- 分组转发：将上层数据（报文）拆分为分组（Packet），并根据路由表转发到下一跳节点
- 拥塞控制：避免网络因数据量过大而拥塞（路由器会采用主动丢包策略，说明网络层参与拥塞控制）

典型设备：路由器（Router）

#### 4. 传输层（Transport Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：负责端到端（源主机进程到目标主机进程）的可靠数据传输，屏蔽底层网络的差异，为上层提供统一的通信接口</span>**

具体作用：

- 分段与重组：将上层的大报文拆分为适合网络传输的小数据段，在接收端重组
- 可靠传输：通过确认机制、重传机制（如 TCP 的三次握手、超时重传）保证数据无丢失、无重复、按序到达
- 流量控制：基于接收端的处理能力动态调整发送速率（如 TCP 的滑动窗口机制）
- 复用与分用：通过端口号（如 TCP/UDP 端口）区分同一主机上的不同应用程序（如 80 端口对应 HTTP，443 端口对应 HTTPS）

典型协议：TCP（传输控制协议，可靠传输）、UDP（用户数据报协议，不可靠但高效）

#### 5. 会话层（Session Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：负责建立、管理和终止两个应用程序之间的会话（即 "对话"），确保通信双方的同步</span>**

具体作用：

- 会话建立与释放：通过三次握手等机制建立会话，通信结束后释放资源
- 会话同步：在数据传输中插入同步点，若传输中断，可从最近的同步点恢复，避免重新传输全部数据
- 会话管理：控制会话的方向（如单工、半双工、全双工）

典型应用：数据库连接的会话管理、远程登录（如 Telnet）的会话控制

#### 6. 表示层（Presentation Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：处理数据的格式转换和表示，确保发送方和接收方能够理解彼此的数据格式</span>**

具体作用：

- 数据格式转换：将应用层的数据转换为网络通用格式（如 ASCII 与 Unicode 的转换）
- 数据压缩与解压：减少数据传输量（如 ZIP 压缩）
- 数据加密与解密：保障数据传输的安全性（如 SSL/TLS 加密）

典型应用：JPEG 图像编码、MP3 音频编码、SSL 加密协议的部分功能

#### 7. 应用层（Application Layer）

**<span style="font-weight:bold;text-decoration:underline">功能：直接为用户应用程序提供网络服务，是用户与网络的接口，</span>**其数据单位是报文（Message）

具体作用：

- 定义应用程序之间的通信协议和交互规则
- 提供特定服务（如文件传输、邮件发送、网页浏览）

典型协议：HTTP（网页访问）、FTP（文件传输）、SMTP（邮件发送）、DNS（域名解析）、Telnet（远程登录）

## 什么是协议？

**<span style="font-weight:bold;text-decoration:underline">协议定义了在两个或多个通信实体之间交换的报文的格式和顺序，以及报文发送和/或接收一条报文或其他事件所采取的动作，</span>**从这个定义中可以看出一个协议包括通信实体和通信规则的三要素

**<span style="font-weight:bold;text-decoration:underline">通信实体表示任何可发送或接收信息的硬件或软件模块</span>**，比如网卡这个硬件就是一个通信实体，在更多的情况下，通信实体就是一个特定的软件模块，比如下图应用层的浏览器进程和 Web 服务进程都是通信实体，在计算机网络中，应用层、运输层、网络层一般都是软件模块，而数据链路层和物理层一般采用硬件（网卡）实现，这里的相同层的实体称为对等实体，对等实体之间在逻辑上是直接通信的

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cnSq0Rx1785553649bP.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">网络协议中的通信规则主要以下三个要素组成：</span>**

- **<span style="font-weight:bold;text-decoration:underline">① 语法，</span>**即传输数据或者控制信息的格式或者结构
- **<span style="font-weight:bold;text-decoration:underline">② 语义，</span>**即需要发出何种请求，做出何种响应和动作
- **<span style="font-weight:bold;text-decoration:underline">③ 时序（也称为同步）</span>**，即发出请求，做出响应和动作的先后顺序

可以类比两个人打电话，语法规定必须说普通话、句子有主谓结构，不能乱哼哼；语义规定 "喂你好" 代表打招呼，"挂了"代表结束通话；时序规定不能两人同时抢着说话，一人说完停顿，另一人再回应

对于**<span style="font-weight:bold;text-decoration:underline">语法</span>**， 规定协议传输数据 / 控制信息的格式、结构、编码、信号电平、帧结构，主要是管「**<span style="font-weight:bold;text-decoration:underline">数据怎么组织、长什么样子</span>**」  ，我们来举几个例子，比如以太网规定一个数据链路层的 MAC 帧必须按固定结构排列，看下图：

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cRTYuHJ1785553649ja.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

MAC 帧的结构是【前导码 (8B) + 目的 MAC (6B) + 源 MAC (6B) + 类型字段 (2B) + 数据 + FCS 校验 (4B)  】， 这就是数据链路层的 MAC 协议的**<span style="font-weight:bold;text-decoration:underline">语法</span>**：强制规定每一字段占多少字节、先后摆放顺序，少一段 / 长度不对就是非法帧，直接丢弃；再比如， HTTP 规定请求行固定格式：<span style="text-decoration:underline">方法 路径 版本 \r\n</span>，<span style="text-decoration:underline">GET /index.html HTTP/1.1\r\n</span> 就是一个合法的 HTTP 请求，如果写成乱序 HTTP/1.1 GET /index，服务器进程是识别不了的，违反了应用层 HTTP 协议的语法

对于**<span style="font-weight:bold;text-decoration:underline">语义</span>**，规定协议的每个字段、每个报文代表什么含义、该执行什么操作，主要是管「**<span style="font-weight:bold;text-decoration:underline">数据是什么意思、要做什么事</span>**」  ，比如 HTTP 协议中的响应状态码语义：

- 200 OK：其语义是请求成功，正常返回页面数据
- 404 Not Found：其语义是你要访问的资源不存在
- 500 Internal Server Error：其语义是服务器内部出错

在 HTTP 响应状态码中的数字本身是协议语法，而数字代表的含义就是语义；再比如在 TCP 协议中，其头部有 6 个标志位【SYN、ACK、FIN、RST 等】 这些控制标志位都有自己的语义：

- SYN=1：语义是「请求建立连接」
- FIN=1：语义是「请求断开连接」

对于**<span style="font-weight:bold;text-decoration:underline">时序（同步）</span>**，固定了协议的通信双方动作执行的先后顺序、匹配时机、超时等待、速率同步，管「**<span style="font-weight:bold;text-decoration:underline">谁先发、谁后回、多久没收到算失败</span>**」，比如：

- TCP 协议中的三次握手时序，固定顺序不能乱
- 如果发送方发数据包后，必须等待接收方的 ACK 确认 ， 如果规定 1 秒内没收到 ACK，就重新发包，这个等待、重传的时间规则属于时序
- 在停止等待协议中， 发 1 个包 → 等 ACK → 再发下一个，不能连续狂发，收发交替顺序就是时序

**<span style="font-weight:bold;text-decoration:underline">计算机网络的各层及其协议的集合就是网络的体系结构</span>**，换种说法，计算机网络的体系结构就是这个计算机网络及其构件所应完成的功能的精确定义。需要强调的是：这些功能究竟是用何种硬件或软件完成的，则是一个遵循这种体系结构的实现的问题。体系结构的英文名词 architecture 的原意是建筑学或建筑的设计和风格，它和一个具体的建筑物的概念很不相同。例如，我们可以走进一个明代的建筑物中，但却不能走进一个明代的建筑风格之中。同理，我们也不能把一个具体的计算机网络说成是一个抽象的网络体系结构

总之，**<span style="font-weight:bold;text-decoration:underline">体系结构是抽象的，而实现则是具体的，是真正在运行的计算机硬件和软件</span>**。就是说的分层体系结构是描述每一层需要做哪些事情，具体这些事情是怎么做的，怎么实现的，这不是分层体系结构管理范围；分层体系结构告诉你网络要分成几层，每一层要有哪些功能，具体在一台计算机上如何实现这些功能，就看具体的操作系统和计算机硬件是如何实现的

## TCP/IP 协议栈

这一小节我们来看 TCP/IP 协议栈，在这里不用去抠细节，对 TCP/IP 协议栈有个总体的了解即可，TCP/IP 协议栈由应用层、运输层、网络层、数据链路层和物理层 5 个层次组成，每层都有若干个协议，一个协议层能够用软件、硬件或两者的结合来实现，看下图，两个不同网络中的主机通过一个路由器连接，路由器是工作在网络层，所以路由器的每个接口只包含 3 个层次

### 应用层

应用层是体系结构中的最高层。应用层的任务是**<span style="font-weight:bold;text-decoration:underline">通过应用进程间的交互来完成特定网络应用</span>**。应用层协议定义的是**<span style="font-weight:bold;text-decoration:underline">应用进程间通信和交互的规则</span>**。对于不同的网络应用需要有不同的应用层协议。互联网中的应用层协议很多，如HTTP 协议（它提供了 Web 文档的请求和传送）、支持电子邮件的 SMTP 协议和 FTP（它提供了两个主机之间的文件传输） 等等，再比如将向 www.baidu.com 这样对人友好的主机名字转换为 32 比特的网络地址，也是借助特定的应用层协议即域名系统（DNS）完成的。应用层协议分布在多个端系统上，而一个端系统中的应用程序使用协议与另一个端系统中的应用程序交换信息分组。我们把这种**<span style="font-weight:bold;text-decoration:underline">位于应用层的信息分组称为报文</span>**（包括数据和报文头 H1，看下图）

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cBr08LC1785553689o4.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

### 运输层

运输层的任务就是负责**<span style="font-weight:bold;text-decoration:underline">向两台主机中进程之间的通信提供通用的数据传输服务（运输层解决的是不同主机上进程到进程之间的数据传输问题）</span>**。应用进程利用该服务传送应用层报文。所谓 "通用的"，是指并不针对某个特定网络应用，而是多种应用可以使用同一个运输层服务。由于一台主机可同时运行多个进程，因此运输层有复用和分用的功能（通过端口号来实现）。复用就是多个应用层进程可同时使用下面运输层的服务，分用和复用相反，是运输层把收到的信息分别交付上面应用层中的相应进程

运输层主要使用以下两种协议，利用其中的任一个都能运输应用层报文：

- **<span style="font-weight:bold;text-decoration:underline">传输控制协议 TCP(Transmission Control Protocol)：</span>**提供面向连接的、可靠的数据传输服务，这种服务包括了应用层报文向目的地的确保传递和流量控制 (即发送方/接收方速率匹配)，TCP 也将长报文划分为短报文，并提供拥塞控制机制，因此当网络拥塞时，源抑制其传输速率。TCP 数据传输的单位是**<span style="font-weight:bold;text-decoration:underline">报文段</span>**
- **<span style="font-weight:bold;text-decoration:underline">用户数据报协议 UDP (User Datagram Protocol)：</span>**提供无连接的尽最大努力的数据传输服务 (不保证数据传输的可靠性)，没有流量控制，也没有拥塞控制。UDP 数据传输的单位是用户**<span style="font-weight:bold;text-decoration:underline">数据报</span>**

### 网络层

**<span style="font-weight:bold;text-decoration:underline">因特网的网络层负责将称为数据报的网络层分组从一台主机移动到另一台主机（网络层解决的是不同主机之间的数据传输问题），</span>**在一台源主机中的运输层协议 (TCP 或 UDP) 向网络层递交运输层报文段和目的地址，就像你通过邮政服务寄信件时提供一个目的地址一样，主机在发送数据时，网络层把运输层产生的报文段或用户数据报封装成分组或包进行传送。在 TCP/IP 体系中，由于网络层使用 IP 协议，因此分组也叫作 IP 数据报，或简称为数据报

网络层也包括决定路由的路由选择协议，它根据该路由将数据报从源传输到目的地。因特网具有许多路由选择协议。网络层的具体任务有两个：**<span style="font-weight:bold;text-decoration:underline">第一个任务是通过一定的算法，在互联网中的每一个路由器上生成一个用来转发分组的转发表</span>**；第二个任务较为简单，**<span style="font-weight:bold;text-decoration:underline">就是每一个路由器在接收到一个分组时，依据转发表中指明的路径把分组转发到下一个路由器</span>**。这样就可以使源主机运输层所传下来的分组，能够通过合适的路由最终到达目的主机

### 数据链路层

数据链路层常简称为链路层。我们知道，两台主机之间的数据传输，总是在一段一段的链路上传送的，这就需要使用专门的链路层的协议（**<span style="font-weight:bold;text-decoration:underline">链路层协议解决的是一段链路上传输数据的问题）</span>**。在两个相邻节点之间传送数据时，数据链路层将网络层交下来的 IP 数据报组装成帧，在两个相邻节点间的链路上传送帧

**<span style="font-weight:bold;text-decoration:underline">每一个帧包括数据和必要的控制信息 </span>**(如同步信息、地址信息、差错控制等)，在接收数据时，控制信息使接收端能够知道一个帧从哪个比特开始和到哪个比特结束。这样，数据链路层在收到一个帧后，就可从中提取出数据部分，上交给网络层。控制信息还使接收端能够检测到所收到的帧中有无差错。如发现有差错，数据链路层就简单地丢弃这个出了差错的帧，以免继续在网络中传送下去白白浪费网络资源

**<span style="font-weight:bold;text-decoration:underline">如果</span>**需要改正数据在数据链路层传输时出现的差错 (这就是说，数据链路层不仅要检错，而且要纠错)，那么就要采用可靠传输协议来纠正出现的差错。这种方法会使数据链路层的协议复杂些。不过，这种可靠的传递服务不同于 TCP 的可靠传递服务，TCP 提供从一个端系统到另一个端系统的可靠交付，数据链路层如果提供可靠传输的话，那么提供的是从一段链路上的可靠传输。**<span style="font-weight:bold;text-decoration:underline">并不是所有的数据链路层协议都提供可靠传输</span>**，比如以太网的 MAC 协议就不是可靠传输

### 物理层

在物理层上所传数据的单位是比特。发送方发送 1 (或 0) 时，接收方应当收到 1 (或 0) 而不是 0 (或 1)。因此物理层要考虑用多大的电压代表 "1" 或 "0"，以及接收方如何识别出发送方所发送的比特。物理层还要确定连接电缆的插头应当有多少根引脚以及各引脚应如何连接。当然，解释比特代表的意思，不是物理层的任务

请注意，传递信息所利用的一些物理传输媒体，如双绞线、同轴电缆、光缆、无线信道等，并不在物理层协议之内，而是在物理层协议的下面。因此也有人把物理层下面的物理传输媒体当作第 0 层。以太网具有许多物理层协议：一个是关于双绞铜线的，另一个是关于同轴电缆的，还有一个是关于光纤的，等等。在每种场合中，跨越这些链路移动一个比特是以不同的方式进行的

## 分层服务模型

### 协议 vs 服务

在网络体系结构中，实体表示任何可发送或接收信息的硬件或软件进程，在许多情况下，实体就是一个特定的软件模块，比如运输层中实现 TCP 协议的软件模块就是一个实体（看下图），网络层中实现 IP 协议的软件模块也是一个实体，相同层的实体称为对等实体，比如下图的不同主机上的 TCP 协议就是对等实体，对等实体之间在逻辑上是直接通信的

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/csl9XOx1785553771dS.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">协议是控制两个对等实体 (或多个实体) 进行通信的规则的集合</span>**。协议的语法方面的规则定义了所交换的信息的格式，而协议的语义方面的规则就定义了发送者或接收者所要完成的操作，例如，在何种条件下，数据必须重传或丢弃。**<span style="font-weight:bold;text-decoration:underline">在协议的控制下，两个对等实体间的通信使得本层能够向上一层提供服务。要实现本层协议，还需要使用下面一层所提供的服务</span>**，比如运输层的 TCP 协议对上面应用层协议提供面向链接的可靠传输服务，而要完成 TCP 协议的功能，还需要用到下一层的网络层的 IP 协议提供的两个主机之间传输数据的服务

一定要弄清楚，协议和服务在概念上是很不一样的：

① 首先，**<span style="font-weight:bold;text-decoration:underline">协议的实现保证了能够向上一层提供服务</span>**。使用本层服务的实体只能看见服务而无法看见下面的协议。也就是说，下面的协议对上面的实体是透明的，比如应用层的 HTTP 协议只会用到运输层的面向链接的可靠传输服务，至于运输层是否采用 TCP 协议，这个 HTTP 协议是不清楚，HTTP 协议也没必要清楚运输层采用的是什么协议实现的，运输层只需要向上提供面向链接的可靠传输服务即可

②  其次，**<span style="font-weight:bold;text-decoration:underline">协议是 "水平的"，即协议是控制对等实体之间通信的规则</span>**。**<span style="font-weight:bold;text-decoration:underline">但服务是 "垂直的"，即服务是由下层向上层通过层间接口提供的</span>**

③ 另外，**<span style="font-weight:bold;text-decoration:underline">并非在一个层内完成的全部功能都称为服务。只有那些能够被高一层实体 "看得见" 的功能才能称之为 "服务"</span>**，比如网络层的 IP 协议有路由选择功能，但是这个功能是上层运输层协议看不见的，所以，网络层的路由选择功能不能称为服务，网络层对运输层提供的是主机之间分组转发的服务，上层使用下层所提供的服务必须通过与下层交换一些命令，这些命令在 OSI 中称为服务原语

### SAP

在同一系统中相邻两层的实体进行交互 (即交换信息) 的地方，通常称为服务访问点 SAP (Service Access Point)。服务访问点 SAP 是一个抽象的概念，是本层向上层提供服务的接口标识，用来区分上层不同应用/协议

**<span style="font-weight:bold;text-decoration:underline">物理层的 SAP 就是网卡物理接口</span>**， 用于区分本机用哪一条物理通道（ 比如 eth0、eth1 两个网口  ）收发比特流；看下图 MAC 层的帧格式，**<span style="font-weight:bold;text-decoration:underline">2 个字节的类型字段就是数据链路层的 SAP</span>**，用于区分上层网络层协议，典型的类型字段取值是 0x8000 表示上层使用 IPv4 协议、0x0806 表示上层使用 ARP 协议、0x86DD 表示上层使用 IPv6 协议，链路层收到帧后，用 SAP 判断要把数据交给上层哪个协议（IP、ARP、IPv6 等）

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cqRPTYu1785553771To.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

看下图的网络层 IP 协议的 IP 数据报格式，**<span style="font-weight:bold;text-decoration:underline">网络层的 SAP 就是 IP 数据报头部的 1 字节的协议字段</span>**， 用于区分上层是 TCP、UDP、ICMP、IGMP 等传输层协议 ，协议字段典型的值是 6 表示上层使用 TCP 协议、17 表示上层使用 UDP 协议、1 表示上层使用 ICMP 协议等

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cvug9Vr1785553771dg.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

看上图运输层的 TCP/UDP 协议的格式，**<span style="font-weight:bold;text-decoration:underline"> 传输层向上给应用层提供 SAP 就是 TCP/UDP 端口 </span>**，用于区分一台主机上的应用进程，比如端口 80 表示上层应用进程是 Web 网页服务进程、端口号 22 表示上层应用进程是 ssh， HTTP 使用 TCP 80 端口，80 就是传输层 SAP

### SDU 和 PDU

OSI 把**<span style="font-weight:bold;text-decoration:underline">层与层之间交换的数据的单位称为服务数据单元 SDU </span>**(Service Data Unit)，其实就是**<span style="font-weight:bold;text-decoration:underline">上层交给当前层处理的数据块</span>**，对当前层来说只是纯载荷，不含本层头部。 而**<span style="font-weight:bold;text-decoration:underline">协议数据单元 PDU（Protocal Data Unit）则是对等实体之间交换的数据的单位</span>**，一个 PDU 包括本层首部（控制信息）+ 上层交下来的数据， 看下图

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cdltEwj1785553771NM.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

- 假设在应用层发送一个 HTTP 请求报文（应用 PDU），这个应用报文作为 TCP 的 SDU 交给 TCP，然后加上 TCP 首部 ，得到 TCP 报文段（即运输层的 PDU）
- 运输层的 PDU 作为网络层的 SDU 交给网络层的 IP 协议，然后加上 IP 首部，得到 IP 数据报（即网络层的 PDU）
- 网络层的 PDU 作为数据链路层的 SDU 交给数据链路层的 MAC 协议，然后加上 MAC 帧首部和帧尾部，得到 MAC 帧（即数据链路层的 PDU）
- 数据链路层的 PDU 作为物理层的 SDU 交给物理层的协议，然后转换成比特流（即物理层的 PDU）通过传输媒体传输出去

注意：可以是多个 SDU 合成为一个 PDU，也可以是一个 SDU 划分为几个 PDU，怎么理解呢？

先来看情况 ①：多个 SDU 合成为一个 PDU

来看一个场景：客户端连续发很小的 HTTP 字符，每次应用层产生一小段数据（每一段都是独立的传输层 SDU），如果开启 Nagle 算法，TCP 不会立刻每段封装一个 TCP 报文段（PDU），而是缓存若干个小 SDU，凑够一定大小后，**<span style="font-weight:bold;text-decoration:underline">把多个 SDU 拼接在一起，只封装一个 TCP 头部，形成单个 TCP 报文段（PDU）</span>** 发给对方

再来看情况 ②：一个 SDU 划分为几个 PDU

上层给下来一个很大的 SDU，本层 PDU 最大承载长度有限，装不下，只能切割成多块，每一块单独封装成本层 PDU，分别发送，**<span style="font-weight:bold;text-decoration:underline">典型场景是：TCP 分段、IP 分片（</span>**以太网 MTU=1500 字节，如果 IP 首部 + TCP 报文段（SDU）的长度超过了 MTU，那么网络层就会将这个 SDU 分片，然后组装成多个 PDU）

### 数据传输效率

来看一个例子，长度为 100 字节的应用层数据交给运输层传送，需加上 20 字节的 TCP 首部。再交给网络层传送，需加上 20 字节的 IP 首部。最后交给数据链路层传送，加上首部和尾部共 18 字节。试求数据的传输效率

数据的传输效率是指发送的应用层数据大小占所发送的总数据大小的比例，应用层数据长度为 100B 时，数据链路层的帧长为：100B + 20B + 20B + 18B = 158B，因此数据传输效率 = 100B / 158B = 63.29%

若应用层数据长度为 1000 字节，数据的传输效率是多少 ？数据长度为 1000B 时，数据链路层的帧长为：1000B + 20B + 20B + 18B = 1058B，数据传输效率 = 1000B / 1058B ≈ 94.5%，传输效率明显提高了

# 第二章：物理层

## 基带信号

物理层解决一段链路上传输的问题，那么，哪些是一段链路呢？看下图，在一个局域网中，两台计算机通过交换机互连，然后这个局域网，通过一台路由器，和其他的网络互连，在这里，就有 4 条链路

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c9qICWo1785758492Un.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

要解决一条链路上传输数据的问题，那么物理层协议需要解决两个问题：

- 一个是具体要采用什么样的传输媒体呢？就是说，局域网中的链路采用什么类型的电线来传输数据，和其他网络连接的链路采用什么类型的电线来传输数据
- 另一个是传输媒体中是怎样传输 0 和 1 的呢？使用的是基带信号，还是带通信号呢？

在这里，传输媒体、基带信号、带通信号，都是通信领域的知识点，所以说，本章的一开始，我们需要掌握一些通信基础知识，实际上，真正属于物理层的内容很少，这一章主要还是学习通信基础知识

### 消息、信息和信号

在通信系统中，**<span style="font-weight:bold;text-decoration:underline">消息是通信中要传递的具体的内容形式</span>**，比如下图包括图片消息、文字消息和语音消息，对于消息，可能还会有视频消息、符号消息等等

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c7EXKbs1785758492ta.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

而**<span style="font-weight:bold;text-decoration:underline">信息则是消息中所包含的有效内容，或者说具有价值的内容</span>**，比如上图你发的文字消息，包含了 3 部分信息，首先是你有约朋友的需求，然后时间是明天，最后就是事件是吃火锅；而**<span style="font-weight:bold;text-decoration:underline">信号则是消息的传输载体</span>**，如果要在电线上传递消息的话，需要将消息转换成电信号，如果要在空气中传递消息的话，则需要将消息转换成电磁波信号，**<span style="font-weight:bold;text-decoration:underline">不管是电信号还是电磁波信号，它们的本质都是某种物理量的变化在介质中的传递</span>**，这里说的物理量是客观存在的可测量属性，比如大小、方向、频率、强度等

**<span style="font-weight:bold;text-decoration:underline">如果某个物理量恒定不变，那么就无法携带信息</span>**，比如使用电线传递电信号，如果在电线上，电压一直保持不变的话，也传递不了任何的信息，看下图，现在往电线上增加 3V 电压一段时间，在电线内部会产生电场，电场会以近似光速（约 2 × 10^8 米/秒）传递到另一端，然后再将电压变成 0V 一段时间，产生的电场会以近似光速传递到另一端，然后再加 3V 一段时间，就这样交替的变化电压值

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cuuiSWm1785758492bj.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

如果 3V 表示二进制 1，0V 表示二进制 0 的话，那么这样，就可以通过电线来传递信息了，这里传递的就是电信号，在计算机系统中，基本都是采用这一种电信号传输数据

### 基带信号

下面一台计算机主机的各个部件采用的就是总线连接，总线上传输的都是电信号，网卡通过 I/O 中线和主机相连，如果这两台计算机相隔不是很远的话，可以通过双绞线直接相连接，此时，一台计算机输出的表示 0 1 序列的电信号，通过网卡，再通过双绞线传输到另一台计算机上，这样就实现了两台计算机的通信

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cF30bZ117857584924w.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

上面这种**<span style="font-weight:bold;text-decoration:underline">频率范围从直流（也就是 0Hz 附近）开始，包含较低的频率成分的电信号，我们称为基带信号</span>**，在计算机系统中，计算机内部产生的电信号是基带信号，基带信号往往包含较多的低频分量，甚至有直流分量，而许多信道并不能传输这种低频分量或直流分量。为了解决这一问题，就必须对基带信号进行调制，调制可分为两大类：

- **<span style="font-weight:bold;text-decoration:underline">一类是仅仅对基带信号的波形进行变换，使它能够与信道特性相适应，变换后的信号仍然是基带信号，这类调制称为基带调制</span>**。由于这种基带调制是把数字信号转换为另一种形式的数字信号，因此大家更愿意把这种过程称为编码
- **<span style="font-weight:bold;text-decoration:underline">另一类调制则需要使用载波进行调制，把基带信号的频率范围搬移到较高的频段，并转换为模拟信号，这样就能够更好地在模拟信道中传输</span>**。经过载波调制后的信号称为**<span style="font-weight:bold;text-decoration:underline">带通信号 </span>**(即仅在一段频率范围内能够通过信道),而使用载波的调制称为**<span style="font-weight:bold;text-decoration:underline">带通调制</span>**

我们先来学习基带调制，即学习基带信号的编码

## 基带调制（编码）

### 不归零（NRZ）编码

不归零编码是最简单的编码，它实现起来非常容易，硬件设计简单，成本较低，看下图，只需要在发射器，设计一个简单的**<span style="font-weight:bold;text-decoration:underline">震荡电路</span>**，如果要发送二进制 1 的话，则给总线加上高电平 +5V 一小段时间，如果要发送二进制 0 的话，则给总线加上低电平 -5V 一小段时间

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cxUFWIH1785758585Ew.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

因为传输每个二进制时，**<span style="font-weight:bold;text-decoration:underline">电压都不会回到 0 电平，所以这种电信号，我们称为不归零编码信号</span>**，但是这种电信号没有同步信息，比如上图最后传输连续的 3 个高电平，接收端很难知道这个 1 的信号是从哪里开始的，如果要在信道中传输这样的信号，需要额外传输一个时钟信号，用于接收端，同步接收信号

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cdMzjxT1785758585fz.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

看上图，CPU 传输这一串二进制到主存，那么在发送数据信号的同时，也需要发送时钟信号，时钟信号中的每个周期，发送一个二进制，这样，主存可以同时收到二进制数据和时钟信号，然后主存的接收器，根据这个时钟信号来接收每个二进制，这种同步方法，称为**<span style="font-weight:bold;text-decoration:underline">外同步法</span>**

这样虽然可以实现同步，很明显，也增加了硬件复杂度和成本，同时，会降低传输效率，如果传输距离稍微长一点的话，一个是硬件成本变高，同时，同步信号也可能会受到干扰，出现相位漂移、幅度衰减等问题，一旦同步信号出现问题，接收端就无法准确采样数据，进而影响数据传输的准确性

**<span style="font-weight:bold;text-decoration:underline">不归零（NRZ）编码电信号用于计算机内部部件传输数据挺好的</span>**，计算机内部部件与部件之间距离非常的短，在计算机内部，不管是内存总线，还是 I/O 总线，可以使用不归零编码的基带信号传输二进制数据；不过，如果要在一个局域网中的两台计算机之间传输数据的话，最好别用这种不归零编码，因为不利于稍微远一点距离的传输，此时可以采用其他编码电信号，比如曼彻斯特编码的电信号

### 归零（RZ）编码

假设正电平表示 1，负电平表示 0，不过，**<span style="font-weight:bold;text-decoration:underline">每个比特传输完成后信号都会归零，所以这种编码，我们称为归零编码</span>**，看下图传输完第一个二进制 1 后，信号立马归 0，然后传输二进制 0，传完立马归零

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cchUCYa1785758585yI.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">接收端可以根据信号的归零特性来确定一位数据的结束，从而实现自同步，不需要额外的同步信号</span>**，这使得接收端的设计相对简单，比如，当接收端收到 0 电平（0V），然后再收到正电平（+5V），就将信号解释成 1，然后再收到 0 电平（0V），当再次收到负电平（-5V）时，就将其解释成 0

不过这种编码的传输效率低：因为每个比特都需要归零，这意味着在每个比特周期内，有一部分时间是空闲的，浪费了传输时间，降低了单位时间内传输的数据量，就是因为**<span style="font-weight:bold;text-decoration:underline">归零需要占用一部分带宽</span>**，所以传输效率受到了一定的影响（也可以这样理解：归零编码的**<span style="font-weight:bold;text-decoration:underline">突变次数比较多，其频率范围就比较大，占用的宽带资源比较多</span>**，很有占用的带宽资源传输的不是有效数据，所以传输效率低）

### 反向不归零（NRZI）编码

在反向不归零编码中，**<span style="font-weight:bold;text-decoration:underline">使用电平的跳变表示 0、电平保持不变表示 1</span>**，看下图，假设前面一直是 5V，也就是说电平保持不变，那么表示 1，接下来要表示 0，那么电压进行跳变，从 5V 变到 -5V，接下来是二进制 0，那么信号跳变到 5V，表示 0，接下来继续跳变到 -5V，表示二进制 0，接下来电平保持不变，表示二进制 1，接下来继续跳变到 5V，表示二进制 0，接下来继续跳变到 -5V，表示二进制 0，接下来电平保持不变，表示二进制 1

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c1jpH931785758585hf.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

当然，你也可以实现成**<span style="font-weight:bold;text-decoration:underline">电平的跳变表示 1、电平保持不变表示 0</span>**，这种反向不归零编码集成了前两种编码的优点，既能实现自同步，又能尽量不损失系统带宽：

- **<span style="font-weight:bold;text-decoration:underline">电平的跳变可以作为时钟信号</span>** 。接收端可以根据电平的跳变来确定数据的边界和节奏，实现自同步，不需要额外专门的时钟线路来同步，降低了硬件设计的复杂度
- 不需要在每个比特周期内都回到零电平，减少了信号的突变次数，在一定程度上减少信号变化的频率，从而有效利用系统带宽，减少带宽的浪费

**<span style="font-weight:bold;text-decoration:underline">当出现连续多个 1 时，信号电平将长时间保持不变，这可能会导致接收端的同步信号丢失</span>** 。例如，若发送了一长串连续的 1（上图最后），接收端可能难以确定数据的比特边界，从而出现误码，这样也导致信号中存在直流分量。这对于一些不能通过直流信号的传输介质来说，会造成信号传输的困难

### 曼彻斯特编码

在曼彻斯特编码中，**<span style="font-weight:bold;text-decoration:underline">每个二进制对应信号的中间都发生电平跳变，电平跳变既作为时钟信号 (用于自同步)，又作为数据信号，比如向下跳变表示 1、向上跳变表示 0，或者采用相反的规定</span>**，看下图，假设在中间向下跳变表示 1，中间向上跳变表示 0，接下来要表示 0，需要向上跳变，所以先设置为 -5V，然后在中间往上跳变，表示 0

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cCHejap17857585857I.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">接收端只要收到了从高电平跳变到低电平的信号，则解释成二进制 1，如果是低电平跳变到高电平的话，则解释成二进制 0，这就是曼彻斯特编码的自同步特性</span>**，而且，你看由于曼彻斯特编码在每个比特周期内，电平都会发生跳变，使得信号在一个周期内的平均电平为零，不存在直流分量。这对传输线路和相关设备十分友好

### 差分曼彻斯特编码

在差分曼彻斯特编码中，**<span style="font-weight:bold;text-decoration:underline">每个二进制对应信号的中间都发生电平跳变，与曼彻斯特编码不同的是，电平跳变仅表示时钟信号，而不表示数据，数据的表示在于每个二进制对应信号开始处是否有电平跳变：无跳变表示 1、有跳变表示 0</span>**（当然，也可以规定无跳变表示 0、有跳变表示 1）

看下图，假设现在前面是 5V，因为要表示二进制 1，所以，二进制对应信号的刚开始不需要跳变，在信号中间，发生一次跳变，用于自同步；接下来，在二进制对应信号的开始处发生一次跳变，表示二进制 0，到达信号的中间，再次发生一次跳变

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/csoDZpJ1785758585P1.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

接下来，在二进制对应信号的开始出发生一次跳变，表示二进制 0，到达二进制对应信号的中间，再次发生一次跳变；接下来，在二进制对应信号的开始出发生一次跳变，表示二进制 0，到达信号的中间，再次发生一次跳变；接下来，在二进制对应信号的开始出不发生跳变，表示二进制 1，到达二进制对应信号的中间，再次发生一次跳变

### 曼彻斯特编码的优缺点

曼彻斯特编码是一种常用于数字通信的线路编码方式，其核心特点是将每个二进制位的中间位置作为跳变点（上升沿或下降沿），既用于表示数据，又作为同步时钟信号。以下是其优缺点的详细分析：

#### 一、优点

1. **<span style="font-weight:bold;text-decoration:underline">自带同步时钟：</span>**每个二进制位的中间都有跳变（如 "0" 表示从低到高跳变，"1" 表示从高到低跳变），接收端可通过跳变提取同步时钟，无需额外的时钟线，简化了通信系统的设计
2. **<span style="font-weight:bold;text-decoration:underline">无直流分量：</span>**信号的高低电平交替出现，长期来看正负脉冲的面积相等，直流分量为零，适合通过信道（如双绞线）传输，可减少信号衰减和对其他设备的干扰
3. **<span style="font-weight:bold;text-decoration:underline">抗干扰能力强：</span>**以跳变表示数据，而非绝对电平，对信道中的噪声和电平漂移不敏感，适合远距离传输（如以太网早期的 10BASE-T 标准）
4. **<span style="font-weight:bold;text-decoration:underline">支持差分编码：</span>**可衍生出差分曼彻斯特编码，通过跳变的有无表示数据（而非跳变方向），进一步增强抗干扰能力，适用于高速通信（如令牌环网）

#### 二、缺点

1. **<span style="font-weight:bold;text-decoration:underline">编码效率低：</span>**每个二进制位需要两个电平状态（如 "0" 对应 "低 - 高"，"1" 对应 "高 - 低"），实际传输速率是数据速率的 2 倍，带宽利用率低，不适合高速率场景（现代高速通信多采用更高效的编码，如 4B/5B 编码）
2. **<span style="font-weight:bold;text-decoration:underline">占用带宽较大：</span>**因为曼彻斯特编码后的信号跳变更加频繁，根据傅里叶变换原理，信号变化越快，其包含的高频成分就越多，这就要求传输信道具有更宽的带宽来保证信号能够无失真地传输。在一些带宽资源有限的通信场景中，使用曼彻斯特编码可能会面临带宽不足的问题，或者需要投入更多成本来拓宽传输带宽
3. **<span style="font-weight:bold;text-decoration:underline">实现复杂度较高</span>**
相比简单的 NRZ（非归零编码），曼彻斯特编码需要在发送端生成跳变信号，接收端需要解析跳变方向或有无，硬件实现更复杂，成本略高

**<span style="font-weight:bold;text-decoration:underline">曼彻斯特编码的核心优势在于自同步和无直流分量，适合中低速、短距离的数字通信（如早期以太网）</span>**；但由于编码效率低，在高速率场景中逐渐被更高效的编码方式替代。其衍生的差分曼彻斯特编码在抗干扰方面表现更优，曾用于令牌环等网络标准

## 带通调制

带通调制就是使用载波进行调制，把基带信号的频率范围搬移到较高的频段，并转换为模拟信号，这样就能够更好地在模拟信道中传输。经过载波调制后的信号称为**<span style="font-weight:bold;text-decoration:underline">带通信号 (即仅在一段频率范围内能够通过信道)</span>**，从计算机输出的基带信号，可以通过 3 种带通调制方式，得到带通信号，分别是振幅键控、频移键控以及相移键控，我们分别来看

### 振幅键控（Amplitude Shift Keying，简称 ASK）

**<span style="font-weight:bold;text-decoration:underline">振幅键控，是指通过改变带通信号的振幅来表示二进制的 0 和 1</span>**，比如，用一种固定振幅表示二进制 1，用零振幅表示二进制 0，看下图上面的基带信号，表示 1 0 1，经过振幅键控的调制后，得到下面的一个带通信号

在这里，有两种信号状态，使用这一种固定振幅表示二进制 1，使用零振幅表示二进制 0，当然，你也可以使用另一种不同的固定振幅来表示二进制 0

### 频移键控（Frequency Shift Keying，简称 FSK）

**<span style="font-weight:bold;text-decoration:underline">频移键控，就是通过改变带通信号的频率来传递二进制信息</span>**，比如，用较低频率表示二进制 1，较高频率表示二进制 0，看下图，上面表示 101 的基带信号，通过频移键控，被调制成下面这样一个带通信号

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cYAPI9I1785758672dZ.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

在上图下面的波形中，有两种不同频率的波形，其中频率较低的波形表示 1，较高频率的波形表示二进制 0。当然，你也可以用较高频率表示二进制 1，较低频率表示二进制 0，总之，在频移键控调制方式下，得到的带通信号有 2 种不同的频率，分别表示二进制 0 和 1

### 相移键控（Phase Shift Keying，简称 PSK）

再来看相移键控，首先，我们得回顾下波型图中的**<span style="font-weight:bold;text-decoration:underline">相</span>**是什么意思，φ 就是"初相"（初始相位），表示 t=0 时刻波形的起始位置，比如下图第一个波形，在 t = 0 时刻的相位是 0 度，第二个波形相位是 90度，第三个波形相位是 180 度，第四个波形相位是 270 度

那么相移键控调制方法，就是**<span style="font-weight:bold;text-decoration:underline">使用两个不同的相位来表示二进制 0 和 1</span>**，比如，下图上面表示 101 的基带信号，经过相移键控调制后，得到下图下面的一个带通信号

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cza7HgF1785758672HO.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

相位为 0 的信号表示二进制 1，相位为 180度的信号表示二进制 0，在这个带通信号中，有两种频率和振幅都相同，但是相位不同的信号，分别表示二进制 1 和 0，这就是相移键控调制

### 码元、波特率、比特率

在波形图中，**<span style="font-weight:bold;text-decoration:underline">代表不同离散值的基本波形就称为码元</span>**，比如下图每个波形图都有三个码元，第一个码元代表二进制 1，第二个码元代表二进制 0，第三个码元代表二进制 1

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c3j7eYz1785758672AU.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

在**<span style="font-weight:bold;text-decoration:underline">单位时间内（即 1 秒）传输码元的数目，就是码元传输速率</span>**，也称为**<span style="font-weight:bold;text-decoration:underline">传码率，传码率的单位是波特</span>**，因此，传码率也称为**<span style="font-weight:bold;text-decoration:underline">波特率</span>**，有的时候也称为**<span style="font-weight:bold;text-decoration:underline">调制速率</span>**，如果每个码元的长度是 TB（看上图），也就说传输一个码元的时间是 TB 秒，那么传码率，或者是波特率 RB = 1/TB；**<span style="font-weight:bold;text-decoration:underline">数据传输率是单位时间内传输比特数目，也称为比特率，单位是比特每秒（即 b/s）</span>**，在上图中，每个码元携带 1 个比特的数据，所以，这里的比特率是等于波特率的

注意，在时域方波中（看下图），随着时间，电压的取值只有 2 种，高电平 3V 和低电平 0V，那么在这里，表示一个离散值的基本波形也称为一个码元，下图第一个码元表示二进制 1，第二个码元表示二进制 0，第三个码元表示二进制 1

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cvcwGIo1785758672zJ.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

上图，传输一个码元需要 TB 的时间，3 个码元携带了 3 个比特，每个码元的传输时间和每个比特的传输时间都是一样的，那么这里的比特率也是等于波特率

来看一个问题：数据率为 10Mbit/s 的以太网在物理媒体上的码元传输速率 (即码元/秒) 是多少？以太网发送的数据都使用曼彻斯特编码的信号，看下图：

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c9ssGkB1786755150po.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

可以看出，数据率为 10Mbit/s 的以太网就表明，在以太网适配器中，在进行曼彻斯特编码之前，基带信号每秒发送 10×10^6 个码元。**<span style="font-weight:bold;text-decoration:underline">但是经过曼彻斯特编码之后，原来的信号源的每一个码元都变成了两个码元</span>**，因此，最后经过网络适配器发送到线路上的码元速率是每秒 20×10^6 个码元，即速率是每秒 20 兆码元

## 多进制键控调制系统

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c9EOfoQ1785758723ZU.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

在上图这种二进制键控调制系统中，**<span style="font-weight:bold;text-decoration:underline">每个码元只能传输 1 比特的数据</span>**，其传输效率不高，为了提高数据传输效率，最有效的办法就是使得一个码元传输多个比特的数据，也就是我们接下来要学习的多进制键控调制系统

### 多进制振幅键控（MASK）

多进制振幅键控 MASK，下图上面是一种基带多进制信号，这里有 4 个离散的数值，分别是 00、01、10、11，所以，这是一个基带 4 进制信号，如果使用电压表示的话，可能 0V 表示 00 两个比特，3V 表示 01 两个比特，6V 表示 10 两个比特，9V 表示 11 两个比特，这个电压值只是举例哈，这样的话，**<span style="font-weight:bold;text-decoration:underline">一个码元就可以携带 2 比特的数据</span>**了，如果要调制成带通信号的话，可以**<span style="font-weight:bold;text-decoration:underline">使用 4 种不同的固定振幅的波形来调制</span>**

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/chRn46X1785758723kV.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

看上图的下面，振幅为 0 的波形表示 00，上图第一个不同振幅的波形表示 01，第二个不同振幅的波形表示 10，第二个不同振幅的波形表示 11，在这种通信传输系统中，会有**<span style="font-weight:bold;text-decoration:underline"> 4 种不同振幅的信号</span>**，分别表示 00、01、10、11 这四个数值，每种不同振幅的波形就是一个码元，每个码元携带 2 比特的数据，这种信号称为 4 进制信号，也可以称为 4 ASK 信号，这里的 M = 4，表示有 4 种信号状态，每一个码元（或者说每一种信号）携带 log<sub>2</sub>M（也就是是 log<sub>2</sub>4 = 2）个比特；如果是 8 ASK 信号，就需要 8 种不同振幅来表示，每一种振幅表示一个整数信号，那么 8 ASK 信号的话，M = 8，每个码元携带 log<sub>2</sub>8 =  3 个比特

### 多进制频移键控（MFSK）

看下图 4 进制信号，需要 4 种**<span style="font-weight:bold;text-decoration:underline">不同频率的波形</span>**来分别表示 4 个离散的值，这里 f1 表示 00，f2 表示 01，f3 表示 11，f4 表示 10，每一种不同频率的波形就是一个码元

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cS4S83t1785758723Km.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

上图是 4FSK 信号，每个码元携带 2 个比特数据，如果是 8FSK 信号的话，就需要 8 种不同频率的波形来分别表示 8 个离散的值，每个码元携带 3 个比特数据

### 多进制相移键控（MPSK）

看下图（a）的 4 进制信号，**<span style="font-weight:bold;text-decoration:underline">需要 4 种不同初始相位的波形来分别表示 4 个离散的值</span>**，初始相位为 0度表示 01，90 度表示 00，180 度表示 10，270 度表示 11，这就是 4PSK 信号，也称为**<span style="font-weight:bold;text-decoration:underline">正交相移键控 OPSK</span>**，这种信号的每个码元携带 2 个比特数据

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/coIE3UF178575872308.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

如果是 8PSK 信号的话（上图 b），就需要 8 种不同初始相位的波形来分别表示 8 个离散的值，每个码元携带 3 个比特数据

现在的问题是，如果我们想让一个码元携带 4 个比特的话，怎么办呢？如果是采用相移键控的话，那么就需要 2^4 = 16 个不同的初始相位的波形来表示，这样的**<span style="font-weight:bold;text-decoration:underline">相邻的相位的距离就更小了，这样抗干扰能力就会减弱，这样会使得误码率增大</span>**，所谓误码率就是错误接收的码元数在传输总码元数中所占的比例，更确切的说，误码率是码元在传输过程中被传错的概率，如果相连相位的距离越小，那么码元被传错的概率就越大，所以，我们**<span style="font-weight:bold;text-decoration:underline">不能单纯的使用这种相移键控的方式，提升码元携带的比特数</span>**，这时，我们可以使用正交振幅调制 QAM

### 正交振幅调制（QAM）

QAM 是一种振幅和相位联合键控的调制方式，在 AQM 中，**<span style="font-weight:bold;text-decoration:underline">信号的振幅和相位作为两个独立的参量，同时受到调制</span>**，比如看下图（a），振幅可以取 A1 和 A2 两个值，然后相位可以取 0 度和 180 度，那么：

- 当波形相位为 0 度，振幅为 A1 时，可以表示 00，振幅为 A2 时，表示 01
- 当波形相位为 180 度，振幅为 A1 时，可以表示 10，振幅为 A2 时，表示 11

这样就可以表示 4QAM 信号，也就是使用正交振幅调制的 4 进制信号，每个码元包含 2 个比特

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cVMRqIL1785758723Lb.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

如果振幅取 4 个不同的值，然后相位也取 4 个不同的值，就可以调制得到 16 种不同的波形，也就是 16 种信号状态（上图 b），每一种不同的波形可以表示 4 位二进制，也就是说，一个码元携带 log<sub>2</sub>16 = 4 个二进制，这就是 16 进制信号，称为 16 QAM；如果振幅取 8 个不同的值，然后相位也取 8 个不同的值，那么就可以调制成 64 QAM 信号了，也就是 64 进制信号，在 64 QAM 中，每个码元可以携带 log<sub>2</sub>64，也就是 6 个比特位

### 波特率和比特率的关系

因为一个 M 进制码元，可以携带 log<sub>2</sub>M 个比特，因此：

- 比特率 Rb = 波特率 RB * log<sub>2</sub>M （b/s）
- 波特率 RB = 比特率 Rb / log<sub>2</sub>M （Baud）

设码元传输率为 1200 Baud，若采用八进制，则数据传输率为 1200 * log<sub>2</sub>8 = 3600 b/s

## 数据通信系统的模型

接下来，我们稍微了解下，通信系统的模型，下图是通信系统的一般模型：

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/chQtdhP17867025220O.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

通信的目的是传输信息。通信系统的作用就是将信息从信源发送到一个或多个目的地。对于电通信来说，首先要把消息转变成电信号，然后经过发送设备，将信号送入信道，在接收端利用接收设备对接收信号作相应的处理后，送给信宿再转换为原来的消息

**<span style="font-weight:bold;text-decoration:underline">信息源 (简称信源) </span>**的作用是把各种消息转换成原始电信号。根据消息的种类不同，信源可分为模拟信源和数字信源

- 模拟信源输出连续的模拟信号，如话筒 (声音→音频信号)、摄像机 (图像→视频信号)
- 数字信源则输出离散的数字信号，如电传机 (键盘字符→数字信号)、计算机等各种数字终端

**<span style="font-weight:bold;text-decoration:underline">发送设备</span>**的作用是产生适合于在信道中传输的信号，使发送信号的特性和信道特性相匹配，具有抗信道干扰的能力，并且具有足够的功率以满足远距离传输的需要。因此，发送设备涵盖的内容很多，可能包含变换、放大、滤波、编码、调制等过程

**<span style="font-weight:bold;text-decoration:underline">信道是一种物理传输媒质，用来将来自发送设备的信号传送到接收端</span>**。在无线信道中，信道可以是自由空间；在有线信道中，可以是明线、电缆和光纤。有线信道和无线信道均有多种物理媒质。信道既给信号以通路，也会对信号产生各种干扰和噪声。信道的固有特性及引入的干扰与噪声直接关系到通信的质量

上图中的噪声源是信道中的噪声及分散在通信系统其他各处的噪声的集中表示。噪声通常是随机的，形式多样的，它的出现干扰了正常信号的传输。关于信道与噪声的问题稍后再讨论

**<span style="font-weight:bold;text-decoration:underline">接收设备</span>**的功能是将信号放大和反变换 (如译码、解调等)，其目的是从受到减损的接收信号中正确恢复出原始电信号。对于多路复用信号，接收设备中还包括解除多路复用，实现正确分路的功能。此外，它还要尽可能减小在传输过程中噪声与干扰所带来的影响

**<span style="font-weight:bold;text-decoration:underline">信宿</span>**是传送消息的目的地，其功能与信源相反，即把原始电信号还原成相应的消息，如扬声器等

信道和电路并不等同。信道一般都是用来表示向某一个方向传送信息的媒体。因此，一条通信电路往往包含一条发送信道和一条接收信道，从通信的双方信息交互的方式来看，可以有以下三种基本方式：

**<span style="font-weight:bold;text-decoration:underline">(1) 单向通信，又称为单工通信</span>****，**即只能有一个方向的通信而没有反方向的交互。无线电广播或有线电广播以及电视广播就属于这种类型，看下图（a）

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cyvmNvA17867025228d.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

**<span style="font-weight:bold;text-decoration:underline">(2) 双向交替通信，又称为半双工通信（上图 b）</span>****，**即通信的双方都可以发送信息，但不能双方同时发送 (当然也就不能同时接收)。这种通信方式是一方发送另一方接收，过一段时间后可以再反过来，比如对讲机

**<span style="font-weight:bold;text-decoration:underline">(3) 双向同时通信又称为全双工通信（上图 c）</span>**，即通信的双方可以同时发送和接收信息，比如电话

单向通信只需要一条信道，而双向交替通信或双向同时通信则都需要两条信道 (每个方向各一条)。显然，双向同时通信的传输效率最高

## 发送时延和传播时延

前面我们学习了波特率和比特率：

- 波特率：每秒传输的码元数量
- 比特率：每秒传输的比特数量

波特率也称为码元传输速率，比特率也称为数据传输速率。你有没有仔细思考过，如何理解 "**<span style="font-weight:bold;text-decoration:underline">传输</span>**" 这两个字，传输速率和传播速率又有什么区别呢？

**<span style="font-weight:bold;text-decoration:underline">传播速率：就是信号比特在传输媒体上的传播速率，也就是单位时间内（每秒）比特信号能够在传输媒体上传播的距离，单位是米/秒</span>**，比如电磁波信号单位时间内，可以在真空中传播 3 * 10^8 米，那么电磁波在真空中的传播速率就是 3 * 10^8 米/秒，其实就是光速（前面，我们说过，光也是一种电磁波）；再比如，电信号在传输媒体（比如双绞线或者同轴电缆）上的传播速率一般是 2 * 10^8 米/秒

**<span style="font-weight:bold;text-decoration:underline">传输速率：结点（可以是计算机、也可以是交换机、还可以是路由器等）每秒可以向所连接的传输媒体或网络注入（也就是发送）多少个比特，单位是比特/秒，</span>**当我们使用速率表示 "比特/秒" 时，就应当将其理解为结点向链路（或网络）发送比特的速率，这也是比特进入链路（或网络）的速率，而不是比特在链路上（或网络上）传播速率，所以说传输速率也可以称为发送速率

### 比特发送（传输）的时序

现在有一条链路链接两个结点（A 和 B），看下图，两个结点之间的链路长度是 600m，假设比特信号在这条链路上的**<span style="font-weight:bold;text-decoration:underline">传播速率是 2 * 10^8 m/s</span>**，这个相当于比特信号在该链路中，1μs 可以向前传播 200m；假设这条链路的**<span style="font-weight:bold;text-decoration:underline">数据传输速率是 1Mb/s</span>**，这个相当于链路上的结点在 1μs 内可以向链路发送 1 比特数据，这就好比，每个结点中，都有一个发射器，这个发射器本质上就是一个振荡电路，这个震荡电路以 1μs 发送 1 比特的速率，向链路中发送比特数据，现在结点 A 发送 2 个比特数据给到结点 B，总共需要多少时间呢？下图在 t = 0μs 时开始发送曼彻斯特编码表示的两个比特信号，一个是比特 1，一个是比特 0

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/caj2nwM17867025628c.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

- 发送 1 个比特需要 1μs，那么在 t = 0.5μs 时，第一个比特（即比特 1） 发送了一半，注意，**<span style="font-weight:bold;text-decoration:underline">一旦比特信号发出就会在链路上传播</span>**，此时因为经过了 0.5 微秒，所以比特 1 的信号传播了 100m 了，**<span style="font-weight:bold;text-decoration:underline">记住，比特的信号是边发送边传播的</span>**

在 t = 4μs 时，结点 B 接收完比特 1 信号，比特 0 往前传播 200m 到达了结点 B；在 t = 5μs 时，结点 B 接收完比特 0 的信号。可以看到从结点 A 开始传输 2 个比特信号开始，到结点 B 接收完 2 个比特信号，一共花费了 5μs 的时间，其中结点 A 发送两个比特花费的时间是 2μs，这个时间称为**<span style="font-weight:bold;text-decoration:underline">发送时延（或者称为传输时延）</span>**，然后两个比特信号在链路上传播花费的时间是 3μs，这个时间称为**<span style="font-weight:bold;text-decoration:underline">传播时延</span>**

### 发送时延和传播时延

**<span style="font-weight:bold;text-decoration:underline">发送时延是主机或路由器发送数据帧所需要的时间，也就是从发送数据帧的第一个比特算起，到该帧的最后一个比特发送完毕所需的时间</span>**，因此发送时延也叫做传输时延 (我们尽量不采用传输时延这个名词，因为它很容易和传播时延弄混)。发送时延的计算公式是：**<span style="font-weight:bold;text-decoration:underline">发送时延 = 数据帧长度 ÷ 发送速率</span>**（发送速率就是链路数据传输速率、或者说，就是链路带宽），比如上面例子中的传输速率是 1Mb/s，发送 2 个比特的发送时延 = 2b ÷ 1Mb/s = 2μs

**<span style="font-weight:bold;text-decoration:underline">传播时延是比特信号在信道中传播一定的距离需要花费的时间</span>**，传播时延 = 信道长度 ÷ 传播速率，比如上面例子中信道长度是 600m，传播速率是 2 * 10^8 m/s，那么传播时延 = 600m ÷（ 2 * 10^8 m/s）= 3μs，那么，上面例子中结点 A 发送 2 个比特给结点 B，总共花费的时间 = 发送时延 + 传播时延 = 2μs + 3μs = 5μs

**<span style="font-weight:bold;text-decoration:underline">发送时延发生在机器内部的发送器中，与传输信道的长度 (或信号传送的距离) 没有任何关系。但传播时延则发生在机器外部的传输信道媒体上，而与信号的发送速率无关，信号传送的距离越远，传播时延就越大</span>**。可以用一个简单的比喻来说明，假定有 10 辆车按顺序从公路收费站入口出发到相距 100km 的目的地。再假定每一辆车过收费站要花费 6 秒钟，而车速是每小时 100 公里

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cny6BUb17867025625N.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

现在可以算出这 10 辆车从收费站到目的地总共要花费的时间：发车时间共需 60 秒 (相当于网络中的发送时延)，在公路上的行车时间需要 60 分钟 (相当于网络中的传播时延)。因此从第一辆车到收费站开始计算，到最后一辆车到达目的地为止，总共花费的时间是二者之和，即 61 分钟

### 例子

来看一个例子，看下图，结点 A 和结点 B 之间的链路信道长度为 1000km，比特信号在链路信道上的传播速率是 2 × 10^8 m/s，那么传播时延 = 1000km / (2 × 10^8 m/s) = 5ms；现在结点 A 有 100MB 的数据块要传送给结点 B（这里的 1M = 2^20，1B = 8bit），假设数据传输率是 1Mb/s（这里的 1M = 10^6），那么发送时延 = 100MB / 1Mb/s = 100 * 2^20 * 8 ÷ 10^6 s ≈ 838.9s

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/cRYvvVA1786702562ec.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

那么，这种情况下，结点 A 给节点 B 发送 100MB 总共需要的时间是：838.9s + 5ms = 838.9s + 0.005s = 838.905s，可以看到，这里发送时延决定了总时延的数值

如果我们将数据传输率（即发送速率）提高 100 倍，即提高到 100Mb/s，那么发送时延 = 100MB / 100Mb/s = 100 * 2^20 * 8 ÷ 10^8 s ≈ 8.389s，传播时延不变还是 5ms，因此总时延 = 8.389s + 0.005s = 8.394s，这个总时延缩写到原来的 1/100

但是，**<span style="font-weight:bold;text-decoration:underline">并非在任何情况下，提高发送速率就能减小总时延</span>**。例如，要传送的数据仅有 1 个字节 (如键盘上键入的一个字符，共 8 bit)。当发送速率为 1 Mbit/s 时，发送时延是：8 ÷ 10^6 s = 8μs。若传播时延仍为 5 ms，则总时延为 5.008 ms。在这种情况下，传播时延决定了总时延。如果我们把数据率提高到1000 倍 (即将数据的发送速率提高到 1 Gbit/s)，不难算出，总时延基本上仍是 5 ms，并没有明显减小

这个例子告诉我们，**<span style="font-weight:bold;text-decoration:underline">不能笼统地认为："数据的发送速率越高，其传送的总时延就越小"</span>**。这是因为数据传送的总时延包括传播时延和发送时延，不能仅考虑发送时延一项

### 时延带宽积

**<span style="font-weight:bold;text-decoration:underline">发送一个比特的时间称为比特时间，一个比特时间内在链路上传播的距离称为比特距离</span>**，看下图，两个结点之间的链路长度是 600m，假设比特信号在这条链路上的**<span style="font-weight:bold;text-decoration:underline">传播速率是 2 * 10^8 m/s</span>**，假设这条链路的**<span style="font-weight:bold;text-decoration:underline">数据传输速率是 1Mb/s</span>**

![图片](http://wechatapppro-1252524126.cdn.xiaoeknow.com/appvpmptkl94774/image/default/c3q9zjB1786702562Pq.png?imageView2/2/q/100|imageMogr2/ignore-error/1)

在这个情况下，发送 1 个比特需要 1μs，所以比特时间就是 1μs，在 1μs 内，信号可以在链路上传播 200m，因此，比特宽度就是 200m

时延带宽积 = 传播时延 × 链路信道带宽（链路信道带宽就是数据传输速率），比如上面例子中的时延带宽积 = (600m ÷ (2 * 10^8m/s)) × 1Mb/s = 3μs × 1Mb/s = 3 * 10-6 s * 1 * 106 b/s = 3b，从上图，你也可以看到，这条链路上最多只会有 3 个比特的数据，所以说，**<span style="font-weight:bold;text-decoration:underline">时延带宽积也可以看成是一条链路信道中，可以注入最多的比特数</span>**

如果现在数据传输速率增加到 10Mb/s，那么时延带宽积 = (600m ÷ (2 * 10^8m/s)) × 10Mb/s = 3μs × 1Mb/s = 3 * 10-6 s * 10 * 106 b/s = 30b，即链路上可以注入 30 个比特，看下图：

数据传输速率 10Mb/s，那么比特时间是 0.1μs，比特宽度是 20m

## 奈氏准则和香农公式

### 奈斯准则

在 1924 年奈奎斯特推导的奈氏准则指出：**<span style="font-weight:bold;text-decoration:underline">在带宽为 W（单位是 Hz）的信道中，若不考虑噪声影响，则码元传输的最高速率是 2W 码元/秒，如果码元传输速率超过了这个上限的话，就会出现严重的码间串扰问题，使得接收端识别不出正确的码元</span>**

也就说，信道的带宽越大，那么信道的数据传输率也就越大，不过要注意哈，奈氏准则是不考虑信道中的噪声的，但是呢，噪声存在于所有的电子设备和通信信道中，由于噪声是随机产生的，它的瞬时值有时会很大，因此噪声会使接收端对码元的识别产生错误 (1 误判为 0 或 0 误判为 1)

### 香农公式

不过，噪声的影响是相对的，如果信号相对较强，那么噪声的影响就相对较小，因此，信噪比就很重要。所谓**<span style="font-weight:bold;text-decoration:underline">信噪比就是信号的平均功率和噪声的平均功率之比，常记为 S/N</span>**，通常大家使用分贝 (dB) 作为度量单位，即：信噪比（dB）= 10 * log<sub>10</sub>(S/N)（dB），当 S/N = 10 时，信噪比 = 10dB，当 S/N = 1000 时，信噪比 = 30dB

在考虑噪声的情况下，1948 年，信息论的创始人香农推导的香农公式指出，**<span style="font-weight:bold;text-decoration:underline">信道的极限数据传输速率 C = W * log</span>****<sub><span style="font-weight:bold;text-decoration:underline">2</span></sub>****<span style="font-weight:bold;text-decoration:underline">(1 + S/N)（b/s）</span>**，这里的 W 就是信道的带宽，单位是 Hz，S 是信道内所传信号的平均功率，N 是信道内的噪声平均功率，当我们知道信噪比后，就可以通过这个公式得到 S/N 的值，然后再知道信道的带宽的话，就可以求出该信道的最大数据传输率 C

从香农公式可以看出，如果信道带宽或信道中的信噪比越大，那么信息的极限传输速率就越高，香农公式指出了信息传输速率的上限，香农公式的意义在于，**<span style="font-weight:bold;text-decoration:underline">只要信息传输速率低于极限传输速率，那么肯定存在某种办法来提升信道的数据传输速率</span>**，至于怎么提升，香农并没有告诉我们具体的办法

现在如果一个信道的带宽已经确定，信噪比也不能再提高了，并且码元传输速率也到了上限值，也就是 2W 码元每秒（奈斯准则），那么还有什么办法来提升数据传输速率呢？

前面，我们学过，数据传输速率等于码元传输速率乘以一个码元携带的比特数，即比特率 Rb = 波特率 RB * log<sub>2</sub>M （b/s），现在码元传输速率，也就是波特率已经达到了极限了，即最大数据传输率 = 2W * log<sub>2</sub>M （b/s），那么可以通过提高这个 log<sub>2</sub>M 来提升数据传输速率，也就是说，**<span style="font-weight:bold;text-decoration:underline">尽量让每一个码元携带更多的二进制</span>**，这就是奈氏准则的意义，它激励工程人员不断的探索调制方法，使得一个码元能携带更多的比特，从而提升数据传输速率

前面，我们学习的频移键控、相移键控、振幅键控、正交振幅调制，等，都是使得一个码元携带多个比特，从而提升数据传输速率，但是，香农公式又告诫工程人员，在有噪声的实际信道中，不论采用多么复杂的调制技术，一个信道的数据传输率，都不会大于香农提出的这个极限的 C 值，所以，信道的最大数据传输率就是在奈斯准则和香农公式这两个结论的影响下，不断的得到优化提高

### 奈氏准则和香农公式的主要区别

**<span style="font-weight:bold;text-decoration:underline">奈氏准则指出，码元传输的速率是受限的，不能任意提高，否则在接收端就无法正确判定码元是 1 还是 0</span>**（因为有码元之间的相互干扰）。奈氏准则是在理想条件下推导出的。在实际条件下，最高码元传输速率要比理想条件下得出的数值还要小些。电信工程技术人员的任务就是在实际条件下，寻找出较好的传输码元波形，将比特转换为较为合适的传输信号。需要注意的是，奈氏准则并没有对信息传输速率 (bit/s) 给出限制。要提高信息传输速率就必须使每一个传输的码元能够代表许多个比特的信息。这就需要有很好的编码技术

香农公式给出了信息传输速率的极限，即**<span style="font-weight:bold;text-decoration:underline">对于一定的传输带宽 (以赫兹为单位) 和一定的信噪比，信息传输速率的上限就确定了。这个极限是不能够突破的</span>**。要想提高信息传输速率，或者必须设法提高传输线路的带宽，或者必须设法提高所传信号的信噪比，此外没有其他任何办法。至少到现在为止，还没有听说有谁能够突破香农公式给出的信息传输速率的极限

香农公式告诉我们，若要得到无限大的信息传输速率，只有两个办法：要么使用无限大的传输带宽（这显然不可能），要么使信号的信噪比为无限大，即采用没有噪声的传输信道或使用无限大的发送功率（当然这些也都是不可能的）
