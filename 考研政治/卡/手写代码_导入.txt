接下来分析顺序表插入操作的时间复杂度和空间复杂度，以下是插入操作的代码实现：
首先，我们要知道这个插入操作的问题规模是顺序表的长度（假设用 n 表示），插入操作在执行时，只有了一个辅助变量 j，它和问题规模 n 无关，因此插入操作的空间复杂度是 O(1)
接下来分析时间复杂度，插入操作的基本语句是 L->data\[j\] = L->data\[j - 1\]，基本语句执行的次数取决于插入元素的位置
如果插入位置是最后一个位置（即第 L->length + 1 的位置），那么不需要执行移动元素的操作，所以最好情况下的时间复杂度是 O(1)
如果插入位置是第一个位置，那么需要移动 n 个元素，那么基本元素需要执行 n 次，所以最差情况下的时间复杂度是 O(n)

首先，我们要知道这个删除操作的问题规模是顺序表的长度（假设用 n 表示），删除操作在执行时，只有了一个辅助变量 j，它和问题规模 n 无关，因此删除操作的空间复杂度是 O(1)
接下来分析时间复杂度，删除操作的基本语句是 L->data\[j - 1\] = L->data\[j \]，基本语句执行的次数取决于删除元素的位置

因为顺序表是用一组地址连续的存储单元依次存储线性表的数据元素，所以可以通过一个简单的地址计算公式，就可以随机访问到顺序表的每一个元素
不过，从另一方面来看，顺序表的这个存储特性也造成了这种存储结构的缺点：在做插入或删除操作时，需移动大量元素，使得插入、删除操作特别的不高效
而且由于数组有长度相对固定的静态特性，当表中数据元素个数较多且变化较大时，操作过程相对复杂，必然导致存储空间的浪费，比如你申请的数组空间是 1000，本来顺序表的元素有将近 1000 个，但是不断地删除了元素，导致顺序表只有 100 个元素，这就导致存储空间的浪费，这个是静态数组的缺点

在内部排序过程中，对尚未确定最终位置的所有元素进行一遍处理称为一趟排序，比如上面的插入排序的外层循环控制趟数，插入排序一共要执行 n - 1 趟
可以看到，整个算法没有使用和数组长度 n 有关的辅助空间，因此空间复杂度是 O(1)，所以直接插入排序是原地排序算法，接下来分析直接插入排序的时间复杂度，请看视频讲解：
视频中，我们说直接插入排序的比较次数和数据移动次数和逆序对数量有关，这个结论参考的是算法 4 这本书，对于其证明，请看下面截图（下面的倒置就是逆序的意思）：
所以，我们可以看到：插入排序所需的时间取决于数组中元素的初始顺序
算法特点
① 直接插入排序是稳定排序算法
② 算法简单，虽然时间复杂度是 O(n^2)，但是如果要排序的数据量很少的话（比如数据大小 n 小于 100），使用直接插入排序是一个很不错的选择，排序速度不慢，而且实现起来很简单
③ 直接插入排序对于部分有序的数组十分高效，如果符合下面 3 个场景之一的数组都是部分有序数组
数组中每个元素距离它的最终有序位置都不远
在一个数组中，一个很大的有序区间后面接一个小的无序区间
数组中只有几个元素的位置不正确（也就是其他的元素都是在最终有序的位置上）
当数组初始状态无序，而且数组长度 n 比较大时，不宜采用直接插入排序
④ 直接插入排序也适用于链式存储结构，对单链表进行插入排序时，无序移动数据，只需比较以及修改相应的指针即可，请看下面视频讲解：
算法优化
直接插入排序采用顺序查找法查找当前记录在已排好序的序列中的插入位置，这个 "查找" 操作可利用 "折半查找" 来实现，由此进行的插入排序称之为折半插入排序（Binary Insertion Sort）
请看下面视频讲解：
从时间上比较，折半查找比顺序查找快，所以就平均性能来说，折半插入排序优于直接插入排序
折半插入排序所需要的关键字比较次数与待排序序列的初始排列无关，仅依赖于数组元素的个数。不论初始序列情况如何，在插入第 i 个数组时，需要经过  次比较，才能确定它应插入的位置。所以当数组的初始排列为正序或接近正序时，直接插入排序比折半插入排序执行的关键字比较次数要少
折半插入排序的元素移动次数与直接插入排序相同，依赖于数组的初始排列。在平均情况下，折半插入排序仅减少了关键字间的比较次数，而记录的移动次数不变。因此，折半插入排序的时间复杂度仍为O (n^2)
因为，我们是在前面有序区间折半查找第一个大于后面待插入元素的插入位置，也就是说后面元素如果和前面元素相等的话，最终也是插入到前面相等元素的后面，所以折半插入排序也是稳定排序算法

快速排序算法的性能分析如下：
① 空间效率：由于快速排序是递归的，因此需要借助一个递归工作栈来保存每层递归调用的必要信息，其容量与递归调用的最大层数一致。最好情况下为 O(log₂n)；最坏情况下，要进行 n-1次递归调用，因此栈的深度为 O(n)；平均情况下，栈的深度为 O(log₂n)
② 时间效率：快速排序的运行时间与划分是否对称有关，快速排序的最坏情况发生在两个区域分别包含 n-1 个元素和 0 个元素时，这种最大限度的不对称性若发生在每层递归上，即对应于初始排序表基本有序或基本逆序时，就得到最坏情况下的时间复杂度为 O(n²)
有很多方法可以提高算法的效率：一种方法是尽量选取一个可以将数据中分的枢轴元素，如从序列的头尾及中间选取三个元素，再取这三个元素的中间值作为最终的枢轴元素；或者随机地从当前表中选取枢轴元素，这样做可使得最坏情况在实际排序中几乎不会发生
在最理想的状态下，即 partition() 能做到最平衡的划分，得到的两个子问题的大小都不可能大于 n/2，在这种情况下，快速排序的运行速度将大大提升，此时，时间复杂度为 O(nlog₂n)
好在快速排序平均情况下的运行时间与其最佳情况下的运行时间很接近，而不是接近其最坏情况下的运行时间。快速排序是所有内部排序算法中平均性能最优的排序算法
③ 稳定性：在划分算法中，若右端区间有两个关键字相同，且均小于基准值的记录，则在交换到左端区间后，它们的相对位置会发生变化，即快速排序是一种不稳定的排序算法。例如，表 L={3,2,2}, 经过一趟排序后 L={2,2,3}，最终排序序列也是 L={2,2,3}，显然，2 与 2 的相对次序已发生了变化
④ 适用性：快速排序仅适用于顺序存储的线性表（因为分区点可以是任何一个元素，也就是说需要快速的随机访问分区点，因此仅仅适用于顺序存储的线性表）
注意：在快速排序算法中，并不产生有序子序列，但每一趟排序后会将上一趟划分的各个无序子表的枢轴(基准)元素放到其最终的位置上
